# Table Talk

**围绕真实旅行场景，学会听懂、接话和表达需求。**

[在线使用](https://henrymeihao.github.io/table-talk-web/) · [33 个场景目录](CURRICULUM.md) · [项目介绍](https://henrymeihao.github.io/writing/table-talk-travel-english/) · [定制与贡献](CONTRIBUTING.md)

旅行时，想跟当地人交流，却缺少词汇和地道表达，很多意思只能拐弯抹角地说。这是我做 Table Talk 的起点。

这个项目主要给我自己使用，也开源出来供你使用和修改。每个 topic 对应一个具体场景：**通常会聊什么、有哪些好用的表达、需要掌握哪些单词。**

由 [henrymeihao](https://github.com/henrymeihao) 创建，借助 AI 完成开发与内容整理。

## 先试咖啡店的新体验

[咖啡店](https://henrymeihao.github.io/table-talk-web/cafe.html) 现在可以先选一个目标：找合口味的饮品、问菜单、打听附近去处，或练习没听懂时怎么接话。自己回答后，再选择往哪个方向聊，三轮表达即可结束。

中文也可以先写下来；卡住时再看提示和参考表达。回应为预设分支，不根据自由输入生成，也不自动评分。原来的对话、词汇、语法和练习保留在折叠参考区。新演练的草稿、自评和复习时间同样本地保存，并纳入首页进度与备份。

目前只有咖啡店采用这一流程，其他 32 个主题仍使用下述课程形式。

## 一节课怎么用

我觉得，先掌握能用上的表达，再逐步扩展词汇，更适合出行前的准备。因此，学习主线只保留一小组必要词块，扩展词汇按需查看，正文可以顺着读。

1. **读对话、听接话**：看对方可能问什么，以及自己可以怎么回答。词语、例句和对话都可朗读，支持慢速和停止。
2. **理解表达**：结合语境解释语法、词语区别和相近说法，而不只给中英文对照。
3. **自己回答**：先完成情境任务，再对照参考表达；随后换一组条件继续练。
4. **回来复习**：按“想不起来／需要提示／能独立表达”自评，首页显示待复习内容、最近练习记录，并可继续上次的学习。

复习使用固定间隔：想不起来约 10 分钟后，需要提示约 1 天后，独立表达约 3 天后。当前不自动批改回答，也不提供发音评分。

## 进度、隐私与使用边界

- **无需注册**：静态网页，没有项目自建的账号系统、服务端数据库或 AI 接口；部署不需要 API Key。
- **进度留在当前浏览器**：回答、收藏、自评、复习日期和阅读位置保存在本地，同一网址下再次进入可以继续，不会每天清空，也不会上传到项目服务器。
- **支持备份**：首页可导出进度 JSON，通过文件或粘贴文本恢复。换浏览器、设备或网址不会自动同步；清除网站数据或使用无痕模式时，请注意备份。备份包含自己的练习回答。
- **读音来自设备语音合成**：声音和可用语音因系统而异，部分语音可能联网，并非真人录音。

静态架构减少了账号与数据库相关风险，但不代表绝对安全；网站托管平台仍可能记录常规访问日志。课程姓名和情境为虚构练习。

课程用于语言练习，目前以旅行服务交流为主。活动课程不能替代现场指导、资格要求或安全培训；学习效果尚未经过系统验证。

## 本地运行

需要 Node.js 18+；下面的预览命令还需要 Python 3。项目没有第三方运行依赖，无需 `npm install`。

```sh
git clone https://github.com/henrymeihao/table-talk-web.git
cd table-talk-web
npm run build
npm test
npm start
```

打开 [本地预览](http://127.0.0.1:4318)。`npm start` 只提供静态文件，不是保存学习数据的服务端。

## 定制自己的版本

可以 Fork 仓库，保留学习流程，换成自己需要的场景、词汇和例句。

- `content/travel.json`：31 个数据驱动的主题，适合从这里修改已有课程。
- `restaurant.html`、`cafe.html` 及对应配置：两个初始主题。
- `cafe-play.js`、`cafe-play-ui.js`、`cafe-play.css`：咖啡店的分支演练内容、状态及界面。
- `app.js`、`style.css`：共用的学习交互和样式。
- `learning-store.js`、`progress-home.js`：进度、自评、复习和首页汇总。
- `pronunciation.js`：词语与句子朗读。
- `scripts/`、`tests/`：静态构建、发布与验证。

修改步骤、数据注意事项和新增主题的限制见 [定制与贡献指南](CONTRIBUTING.md)。请修改源文件，再生成页面；不要直接编辑构建结果。

### 部署到 GitHub Pages

1. Fork 后修改内容，执行 `npm run build` 和 `npm test`。
2. 将源文件和生成的 `docs/` 一起提交。
3. 在仓库 **Settings → Pages** 中选择 **Deploy from a branch**，分支 `main`，目录 `/docs`。

`dist/` 用于本地预览，`docs/` 用于发布，两者都由构建生成。定制后记得更新 README、课程目录中的网址，以及页面中的项目名称和署名，区分原作者与自己的修改。
